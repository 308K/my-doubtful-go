# AGENTS.md

Instructions and high-signal operational context for AI agents working in `my-doubtful-go`.

---

## Toolchain & Runtime Rules

- **Use Bun Exclusively**: Always use `bun` (never `npm`, `pnpm`, `yarn`, or `node`). MyGo CLI expects `bun`.
- **Desktop Framework**: Built on **MyGo (`github.com/egoist/mygo`)**—pure Go (`CGO_ENABLED=0`) invoking native OS webviews (Windows WebView2, macOS WKWebView, Linux WebKitGTK).
- **Go Versioning**: Use latest stable Go (`>= 1.27`). `go.mod` must maintain explicit direct dependencies (especially `github.com/xuri/excelize/v2` and `github.com/openai/openai-go/v3`). Always run `go mod tidy` after modifying Go imports.
- **Frontend RPC Codegen**: `src/mygo.ts` is auto-generated by MyGo. Do not edit it manually; run `bun run generate` whenever Go structs or bound methods in `main.go` change.

## Essential Developer Commands

```bash
# Install frontend dependencies
bun install --frozen-lockfile

# Run all test suites across engine, AI service, and main service
go test -v ./...

# Run Go core pipeline & dynamic formula tests
go test -v ./internal/ar/...

# Run AI service & anonymizer tests
go test -v ./internal/ai/...

# Run a single focused test
go test -v ./internal/ar/ -run TestPipelineAndExportOnSampleDataset

# Typecheck frontend
bun run typecheck

# Build web frontend
bun run build:web

# Regenerate Go <-> TypeScript RPC bindings
bun run generate

# Launch desktop app in development mode (with Vite HMR & DevTools)
bun run dev

# Compile production desktop packages
bun run build
# Cross-compile specific target platforms
bun run build -- -platform "windows/amd64,windows/arm64"
```

## Architecture & Directory Ownership

- **`main.go`**: Desktop process entrypoint. Sets up `SmartARService`, binds it via `mygo.Bind()`, configures WebView window options, manages cross-window chat session persistence (`chatHistory`), exports snapshot state (`GetCurrentPipelineResult`), and injects `--enable-blink-features=CSSTextAutoSpace` into `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` for Windows.
- **`mygo.config.ts`**: Desktop package manifest (app ID, file associations, target binaries).
- **`internal/ar/`**: Pure Go accounting engine (no GUI/DOM dependencies).
  - `engine.go`: 5-step data governance pipeline (structure audit, missing value imputation, 9 anomaly audits, aging calculation, custom rule & master data support).
  - `types.go`: Data models, anomaly definitions, master customer schemas, bad debt provision tables, and aggregation structures.
  - `exporter.go`: High-fidelity Excelize v2 dynamic formula export engine.
  - `engine_test.go`: End-to-end regression test suite matching ground truth numbers.
- **`internal/ai/`**: Pure Go AI Copilot & Agent runtime (built on `github.com/openai/openai-go/v3`).
  - `service.go`: Agent execution engine, function-calling toolchain (aging calculation, anomaly review, rule tuning, proposal confirmation, audit working paper export), streaming responses, thinking intensity control, and provider presets (Volcengine, DeepSeek, Qwen, Ollama, etc.).
  - `anonymizer.go`: Local client-side privacy protection and masking engine for customer names, financial entities, and sensitive identifiers with zero external data leaks.
  - `types.go`: AI message formats, tool signatures, streaming events, and configuration structs.
  - `service_test.go`: Complete suite covering anonymization roundtrips, proposal confirmation cycles, and tool inference.
- **`src/`**: React 19 + TypeScript + Tailwind CSS v4 frontend.
  - `src/mygo.ts`: Auto-generated bridge connecting to `SmartARService`.
  - `src/store.ts`: Zustand store managing UI state, active step navigation, file load status, anomaly filters, audit snapshots, and cross-window sync via `storage` event listeners.
  - `src/style.css`: Tailwind v4 theme, high-contrast text selection tokens, and `text-autospace: normal` global typography rules.
  - `src/components/`:
    - `PipelineStepsView.tsx`: Pipeline step inspection and unified Excel file upload interface.
    - `ARDataTable.tsx`: TanStack virtualized data table for governed AR entries.
    - `AIAssistantDrawer.tsx`: Resizable (20% to 60%) side drawer, quick analysis prompt dispatch, message rollback, and detached independent window support.
    - `AISettingsModal.tsx`: AI provider, model discovery, thinking intensity, and API key management.
    - `RuleSettingsModal.tsx`: Visual editor for bad debt reserve ratios, master customer dictionary, and custom anomaly rules.
    - `AuditReportModal.tsx` & `MarkdownViewer.tsx`: Financial audit working paper preview and export.
    - `OpenSourceLicensesModal.tsx`: Open source license disclosure and third-party notices viewer.
- **`resources/`**: Embedded sample assets (`sample_raw_ar.xlsx`, app icons).

## Strict Repository Conventions

1. **Monochromatic Neutral UI**:
   - The UI adheres to Shadcn neutral black/white palette (`zinc-900`, `zinc-100`, etc.).
   - Color is strictly reserved for the 5-tier risk warning levels (`#77DD77`, `#77BBDD`, `#FFDD88`, `#7777AA`, `#FF8899`) and chart data series.
   - Text selection inside chat message bubbles must maintain legible contrast across both dark and light modes.
2. **Typography & Spacing**:
   - **Never manually add spaces between Chinese and Western/numeric characters**. The system relies on CSS `text-autospace: normal` and WebView2 `CSSTextAutoSpace` runtime support.
   - **No emojis anywhere** in UI copy, code comments, commit messages, or release notes.
3. **Anonymity & Real Data Integrity**:
   - The five original project student names must never appear in UI copy or public documentation.
   - Agent prompts and test cases must always reference valid master customer IDs and tiers (e.g. `CUST006` / `浙江天成精工机械有限公司`, valid ratings `A`, `B`, `C`, `D`). Never invent nonexistent identifiers such as `KH001` or `AA`.
4. **Excel Formula Compatibility**:
   - Never use newer dynamic-array-only functions like `IFS` that fail on older Excel/WPS installations. Always use universally compatible nested `IF(...)` expressions in `internal/ar/exporter.go`.
5. **AI Copilot Network Architecture**:
   - All LLM and API network requests are strictly dispatched by the backend Go process (`internal/ai/service.go`) to prevent browser CORS blocks, respect system proxy configurations, and enforce local privacy desensitization.
   - Configuration files stored in `%APPDATA%\smartar\ai_config.json` must be strictly sanitized against unintentional overwrite of real API keys or user model selections.
6. **Cross-Window Multi-Tasking & State Persistence**:
   - AI assistant window detachment must keep chat history and pipeline snapshots fully synchronized with the main application window via Go state bindings (`GetChatHistory`, `SaveChatHistory`, `GetCurrentPipelineResult`) and browser `storage` events.
   - Snapshot rollbacks must use lightweight delta states to avoid memory bloat.
7. **CI/CD Workflow Constraints (`.github/workflows/release.yml`)**:
   - Must use `actions/checkout@v7` and `actions/upload-artifact@v7`.
   - `actions/setup-go@v7` must use `go-version: 'stable'` with `check-latest: true`.
   - CI must execute `go mod download` prior to `bun run build`.
   - Release assets must strictly adhere to the standardized underscore naming convention:
     - `SmartAR_<version>_Windows_x64_Setup.exe`
     - `SmartAR_<version>_Windows_x64_Portable.exe`
     - `SmartAR_<version>_Windows_arm64_Setup.exe`
     - `SmartAR_<version>_Windows_arm64_Portable.exe`
     - `SmartAR_<version>_macOS_AppleSilicon.dmg`
     - `SmartAR_<version>_macOS_Intel.dmg`
     - `SmartAR_<version>_Linux_x86_64.AppImage`
     - `SmartAR_<version>_Linux_aarch64.AppImage`
     - `smartar_<version>_amd64.deb`
     - `smartar_<version>_arm64.deb`
     - `smartar-<version>-linux-amd64.tar.gz`
     - `smartar-<version>-linux-arm64.tar.gz`
   - Linux AppImages must be packaged via `appimagetool` with `--appimage-extract` to run reliably within containerized and non-FUSE CI runners.
